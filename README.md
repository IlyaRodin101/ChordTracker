# ChordTracker

Веб-приложение на Python, которое определяет аккорды в аудиозаписи и показывает их **по тактам**, как в обычной аккордовой сетке. Работает с поп/рок-музыкой (мажорные и минорные трезвучия) и с джазом (септаккорды, sus, уменьшённые).

Без нейросетей. Основа программы — анализ Фурье: звук раскладывается на частоты, из частот выделяются ноты, из нот собираются аккорды.

## Математическая основа

**Ряд Фурье.** Звук одной ноты можно представить как сумму синусоид с частотами $f_0, 2f_0, 3f_0, \dots$:

$$x(t)=\sum_{k=1}^{K} a_k \sin(2\pi k f_0 t+\varphi_k)$$

Здесь $f_0$ — частота самой ноты (основной тон), а остальные слагаемые — обертоны: более высокие и тихие звуки, которые всегда звучат вместе с нотой. Число $a_k$ показывает, насколько громко звучит $k$-й обертон.

**Преобразование Фурье в программе.** Песня не периодична, поэтому ряд Фурье применяется к коротким кускам звука («окнам»): для каждого окна считается, какие частоты в нём есть и насколько они громкие. Это называется оконным преобразованием Фурье (STFT). В проекте оно реализуется через быстрый алгоритм FFT из `numpy`.

**Чем это помогает.**
- Частоты переводятся в ноты, а ноты складываются в аккорд: это основа распознавания.
- Обертоны объясняют ошибки: нота C сама «содержит» тихие C, G, E, поэтому её можно принять за аккорд, а C и Am7 легко перепутать. Чтобы учесть это, обертоны закладываются в шаблоны аккордов.
- Размер окна задаёт компромисс: длинное окно точнее различает низкие ноты, но размывает время. Подробнее в задаче 1.

## Как это работает

```text
аудио → STFT (Фурье) → HPSS → хроматограмма + басовая хрома
                         ↓
                  ударная часть → доли → такты
                         
хроматограмма по долям → шаблоны аккордов (с обертонами) → сглаживание → сетка тактов
```

## Запуск

Нужен Python 3.10+ и `ffmpeg` (для чтения `.mp3`).

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Откройте http://127.0.0.1:5000, загрузите `.wav` или `.mp3`, выберите режим, при необходимости укажите темп (BPM) и размер такта (по умолчанию они определяются автоматически), нажмите «Распознать».

## Пример результата

```text
| 1: Am      | 2: F       | 3: C       | 4: G       |
| 5: Am      | 6: F       | 7: C       | 8: G  E7   |
| 9: Am      | 10: Dm  F  | 11: C      | 12: G      |
```

Если аккорд меняется внутри такта, показываются оба (`G  E7`: первая половина такта G, вторая E7). Таймкоды сохраняются внутри программы и используются для плеера и проверки точности.

## Задачи

### Задача 1. Преобразование Фурье и хроматограмма

Файлы: `core/fourier.py`, `core/audio_processor.py`

- Загрузить аудио через `librosa.load` (для `.mp3` под капотом работает `ffmpeg`, для `.wav` — `soundfile`). Привести к одной частоте дискретизации (22050 Гц) и к моно.
- Написать собственный STFT на `numpy.fft.rfft`: нарезать звук на окна по 8192 отсчётов с шагом 2048, умножить каждое окно на оконную функцию Хэннинга (она убирает «лишние» частоты на краях окна), посчитать FFT. Окно в 8192 отсчётов — компромисс: частотный шаг около 2,7 Гц хватает, чтобы различать ноты от C2 (≈65 Гц), при этом окно длится 0,37 с, и смена аккордов не размывается. Более низкие ноты баса определяются по их обертонам.
- Разделить спектрограмму на гармоническую часть (гитара, клавиши, бас) и ударную (барабаны, тарелки) методом HPSS: `librosa.decompose.hpss` применяется к модулю нашего STFT. Дальше для аккордов используется гармоническая часть.
- Перевести частоты в ноты: частота `f` бина превращается в номер ноты `69 + 12·log2(f / 440)`, и энергия бина добавляется в одну из 12 нот (C, C#, … B) независимо от октавы. Учитывается диапазон от C2 (≈65 Гц) до примерно 2 кГц, потому что выше идут в основном обертоны и шум. Строй трека, если он отличается от 440 Гц, оценивается через `librosa.estimate_tuning` и вносится как поправка.
- Отдельно посчитать хроматограмму только по низким октавам (65–260 Гц), это нужно, чтобы определять бас.

**Результат:** две хроматограммы трека (обычная и басовая) и спектрограмма для графика.

### Задача 2. Доли, такты и базовое распознавание (поп/рок)

Файлы: `core/rhythm.py`, `core/chord_matcher.py`

- Определить темп и позиции долей. Есть два режима:
  - **Авто:** `librosa.beat.beat_track` по ударной части спектрограммы из задачи 1 (`librosa.onset.onset_strength`). Если программа не уверена в результате (темп «прыгает» или получился странным), в интерфейсе появляется подсказка ввести темп вручную.
  - **Вручную:** музыкант указывает BPM, и доли строятся по ровной сетке: каждая доля через `60 / BPM` секунд, начиная с первого заметного удара (`numpy`). Для треков, записанных под метроном, это даже надёжнее автоматики.
- Собрать доли в такты. `librosa` не умеет находить начало такта сама, поэтому размер задаёт музыкант (4/4, 3/4, 6/8 и т. д.), а при режиме «Авто» берётся 4/4. Доли группируются по числу долей в такте. Чтобы такт не «съехал», подбираем сдвиг: выбираем вариант, при котором сильнее всего совпадают смены аккордов и сильные доли (`numpy`). Сдвиг первой доли тоже можно поправить вручную.
- Усреднить хроматограмму внутри каждой доли (`numpy`). Так арпеджио и перебор склеиваются в один аккорд.
- Собрать 24 шаблона (12 мажорных и 12 минорных трезвучий) плюс «нет аккорда» (`N`) для пауз. Шаблон строится с учётом обертонов из ряда Фурье: каждая нота аккорда добавляет единицу в свою ноту, а также меньшие значения в ноты её обертонов (2-й обертон — та же нота на октаву выше, 3-й — квинта, 4-й — снова та же нота, 5-й — терция и т. д.; вес падает с номером обертона). Так шаблон C-мажора выглядит так же, как настоящий звук аккорда, а не «1 на C, E, G и 0 на остальных».
- Для каждой доли выбрать шаблон, который больше всего похож на хрому (косинусное сходство, `numpy`/`scipy`).
- Для каждого такта оставить один аккорд, а если внутри такта аккорд сменился, то два-три (по долям).

**Результат:** список «номер такта → аккорды» для поп/рок-треков.

> Ручная сетка с постоянным BPM подходит только для треков с ровным темпом. В живой записи, где темп плавает, она будет понемногу «уезжать», и для таких треков лучше оставлять режим «Авто».

### Задача 3. Джазовый режим и сглаживание

Файл: `core/chord_matcher.py`

- Добавить шаблоны для `7`, `maj7`, `m7`, `m7b5`, `dim7`, `sus2`, `sus4`. Всего получится около 100 шаблонов (у `dim7` только 3 различимых варианта). Шаблоны строятся так же, как в задаче 2, с учётом обертонов.
- Учитывать бас: если самая сильная низкая нота (из басовой хромы) совпадает с корнем аккорда, его оценка растёт (`numpy`). Это помогает различать похожие аккорды, например C и Am7 или Cmaj7 и Em.
- Подобрать веса обертонов так, чтобы число ошибок на тестовых треках было минимальным (простой перебор нескольких значений).
- Сгладить результат, чтобы убрать случайные скачки от проходящих нот: для каждой доли брать самый частый аккорд среди соседних (`scipy`/`numpy`). Для сложных случаев можно использовать алгоритм Витерби.
- Сглаживание идёт по долям, но с учётом границ тактов: смена аккорда на первой доле такта считается нормальной, а смена на слабой доле требует более уверенного сигнала.

**Результат:** переключаемые режимы «Базовый» и «Расширенный», стабильная последовательность аккордов по тактам.

### Задача 4. Веб-интерфейс и визуализация по тактам

Файлы: `app.py`, `templates/index.html`, `static/`, `core/visualizer.py`

- Сделать сервер на `Flask`: страница загрузки файла и форма с параметрами: режим (базовый/расширенный), темп BPM (авто или число), размер такта (авто или из списка) и сдвиг первой доли. Параметры можно изменить после первого анализа и пересчитать сетку без повторной загрузки файла.
- Показать аккорды в виде сетки тактов (HTML + CSS Grid): по 4 такта в строке, в каждой ячейке номер такта и аккорд(ы). Если аккордов в такте два, ячейка делится пополам. Так результат выглядит как обычная аккордовая шпаргалка.
- Скачивание результата в `.txt` в том же формате «такт: аккорд».
- Нарисовать через `matplotlib` (на сервере включить бэкенд `Agg`) два графика: спектрограмму (результат Фурье: время, частота, громкость) и хроматограмму (время, 12 нот). По горизонтали отметить границы тактов.
- Дать исправить результат вручную: клик по ячейке меняет аккорд, результат можно скачать уже с правками.
- *Если останется время:* HTML-плеер, подсвечивающий текущий такт в сетке (по сохранённым таймкодам долей), и автоматическое определение тональности (`librosa`). Тональность в основном алгоритме не используется: аккорды определяются по корню шаблона и басу.

**Результат:** работающее приложение, которое выдаёт сетку аккордов по тактам и графики.

### Задача 5. Тестирование и оценка точности

Файлы: `evaluation/evaluate.py`, `tests/`

- Собрать 5–6 треков с известными аккордами: 2 с одним инструментом (гитара или фортепиано), 2 полных микса поп/рок, 1–2 джазовых. Из-за авторских прав в репозиторий класть только короткие фрагменты (20–30 секунд) или собственные записи, а для остальных треков хранить только названия и разметку.
- Записать эталонные аккорды с таймкодами в `.lab`-файлы (`начало конец аккорд`). Для сравнения такты переводятся обратно во время по найденным долям.
- Посчитать точность через `mir_eval.chord`: доля времени, на которой найденный аккорд совпал с эталонным. Для поп/рока сравнение по мажору/минору, для джаза — с учётом септаккордов.
- Отдельно проверить определение тактов: сколько тактов начинается на правильной доле (то есть сетка не съехала).
- Провести эксперименты для отчёта: точность с обертонами в шаблонах и без них; собственный STFT и `librosa.stft` (результат должен совпадать); окно 4096, 8192 и 16384 отсчётов.
- Написать автотесты на `pytest`: собственный STFT совпадает с `librosa.stft`, чистая нота A4 (440 Гц) попадает в хрому A, шаблоны, группировка долей в такты, ручной BPM и размер, формат вывода.

```bash
python evaluation/evaluate.py --audio tests/audio --labels tests/annotations
pytest tests/
```

**Результат:** таблица точности по каждому треку и общий вывод о том, где алгоритм ошибается.
